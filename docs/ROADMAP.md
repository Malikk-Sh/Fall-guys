# Wobble Rush 3D — чек-лист улучшений

Документ описывает полный план превращения текущего прототипа обстакл-рейсера в **кооперативную игру
на двух игроков** в духе _It Takes Two_, с попутной прокачкой графики, звука, камеры, сети,
производительности и стабильности.

Чек-лист рассчитан на передачу нейросети: каждый пункт самодостаточен — в нём есть цель, конкретные
файлы и критерий приёмки.

---

## Как пользоваться

Формат пункта:

```
- [ ] КОД-NN · Название                                   [приоритет]
  Зачем:        какую проблему решает
  Файлы:        что править или создавать
  Готово когда: проверяемый критерий приёмки
```

## Состояние прототипа на старте

Проверено чтением всех 19 файлов исходников (~99 КБ).

**Что работает хорошо и это надо сохранить:**

- Комнаты, лобби, четырёхбуквенные коды, миграция хоста.
- Сервер владеет сидом трассы, сам выводит чекпоинты и валидирует финиш — гонку нельзя «срезать».
- Детерминированная процедурная генерация: 7 шаблонов сегментов из одного сида.
- Абстракция ввода: клавиатура и тач-джойстик за единым интерфейсом.
- Headless-стенд для тестов: `server/client-loader.mjs` умеет грузить клиентские ES-модули в Node,
  подменяя `/vendor/three.module.js` на npm-пакет. Редкая и очень полезная штука.
- Респонсивный CSS с учётом `env(safe-area-inset-*)`.

**Что сломано или отсутствует:**

| Проблема                                                                                                                                                                                                                                                                   | Где                                                         |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- |
| **Звука нет вообще.** Ни одного упоминания Web Audio во всём репозитории                                                                                                                                                                                                   | —                                                           |
| **Часы не синхронизируются.** Сервер шлёт `serverTime` в `hello`, `pong` и каждом снапшоте — клиент не читает ни один. Фаза препятствий берётся из локального `Date.now()`, поэтому у игроков с расхождением системных часов вертушки бьют по тем, кто визуально увернулся | `client/net/NetworkManager.js`, `client/main.js` → `loop()` |
| **Нет буфера снапшотов.** Удалённый игрок лерпится к _последнему_ пакету, а не интерполируется между двумя → постоянное отставание и рывки                                                                                                                                 | `client/game/Player.js` → `applyRemote`                     |
| **Нет боковых коллизий.** Есть только приземление сверху; перила созданы с `collider:false` и являются декорацией. Столкновений игрок-игрок нет                                                                                                                            | `client/game/Course.js` → `surfaceAt`                       |
| **Тень не следует за игроком.** Ортографическая камера тени прибита к началу трассы — после второго сегмента теней нет                                                                                                                                                     | `client/main.js` → `createScene()`                          |
| **Каждый вызов `box()` создаёт новый материал** → сотни материалов и переключений шейдера на трассу                                                                                                                                                                        | `client/game/Course.js` → `material()`                      |
| Постобработки нет, геймпада нет, переподключения нет, линтера и типов нет                                                                                                                                                                                                  | —                                                           |

**Блокер номер ноль.** Код написан в предельно плотном стиле: в `styles.css` есть строка на 1867
символов, в `main.js` весь рендер-цикл — одна строка на 1513 символов. Номера строк бесполезны как
якоря для правок, а нейросеть такие строки надёжно редактировать не сможет. Поэтому `TOOL-01`
(переформатирование) обязателен первым — иначе весь остальной чек-лист неисполним.

## COOP · Кооперативный режим — главное

Основной принцип, заимствованный у _It Takes Two_: **асимметричные дополняющие способности плюс
преграды, которые физически невозможно пройти в одиночку.** Не «вдвоём быстрее», а «одному никак».

### Каркас

- [ ] **COOP-01 · Режим на двоих и роли** `P0`
      Зачем: базис всего раздела.
      Файлы: `server/coopRules.js`, `server/index.js`, `client/main.js`, `client/ui/UI.js`.
      Готово когда: комната ровно на 2 игроков; сервер назначает роли **ИСКРА** и **ГРУЗ**; роль видна в лобби и HUD.

- [ ] **COOP-02 · Асимметричные способности** `P0`
      **ИСКРА** — лёгкая: выше прыжок, есть планирование, луч-активатор, светит в тёмных зонах; сдувается ветром.
      **ГРУЗ** — тяжёлая: удар сверху, давит тяжёлые плиты, не сдувается ветром, может подбросить напарника; прыжок ниже.
      Файлы: `client/game/Player.js`, `client/game/abilities/`.
      Готово когда: ни одна секция кооп-главы не проходится одной ролью.

- [ ] **COOP-03 · Общая судьба** `P0`
      Зачем: без общей цены за ошибку кооп распадается на два параллельных забега.
      Файлы: `server/coopRules.js`.
      Готово когда: общий чекпоинт, общий таймер, финиш засчитывается только когда дошли оба.

- [ ] **COOP-04 · Оживление напарника** `P0`
      Зачем: превращает падение из личной неудачи в общую задачу.
      Файлы: `client/game/Player.js`, `server/coopRules.js`.
      Готово когда: упавший становится «пузырём» у последнего чекпоинта, напарник возвращает его касанием;
      авто-оживление через 12 секунд, чтобы не было тупика.

- [ ] **COOP-05 · Владение объектами** `P0`
      Зачем: без арбитража два клиента будут спорить за состояние одной платформы.
      Файлы: `server/coopRules.js`.
      Готово когда: у объекта есть владелец (первый коснувшийся), сервер разрешает конфликты по метке
      времени; импульсы игрок→игрок шлёт инициатор, сервер ограничивает модуль и ретранслирует.

### Механики

- [ ] **COOP-06 · Парные плиты** `P0`
      Двое встают на две плиты одновременно — открываются ворота. Обучающая механика первой главы.
      Готово когда: ворота не открываются в одиночку никаким способом.

- [ ] **COOP-07 · Катапульта** `P1`
      ИСКРА встаёт на конец рычага, ГРУЗ бьёт ударом сверху по другому концу — ИСКРА улетает через пропасть
      и открывает путь напарнику. Классический бит «по очереди».
      Готово когда: сила запуска зависит от высоты удара; ИСКРА стабильно долетает при правильном исполнении.

- [ ] **COOP-08 · Энергетический мост** `P1`
      ИСКРА держит луч на излучателе — пока держит, существует мост, по которому бежит ГРУЗ. Сама ИСКРА
      по своему мосту пройти не может.
      Готово когда: мост исчезает при уводе луча; ГРУЗ падает, если ИСКРА отвлеклась.

- [ ] **COOP-09 · Трос** `P1`
      Упругая связь между игроками с ограничением длины. Даёт: раскачку над пропастью (один держится,
      второй летит), вытягивание упавшего, рогатку для дальнего прыжка.
      Файлы: решается как ограничение расстояния на фиксированном шаге у обоих клиентов — позиции уже
      синхронизированы, отдельный авторитет не нужен.
      Готово когда: раскачка предсказуема, трос не «взрывается» при лаге.

- [ ] **COOP-10 · Синхро-ворота** `P2`
      Ворота открываются, только если оба пересекли линию в пределах 400 мс друг от друга.
      Готово когда: HUD показывает индикатор синхронности перед воротами.

- [ ] **COOP-11 · Бросок напарника** `P2`
      ГРУЗ поднимает ИСКРУ и бросает через препятствие; сила и направление задаются прицеливанием.
      Готово когда: траектория показывается пунктиром обоим игрокам.

- [ ] **COOP-12 · Зеркальные зоны** `P2`
      Управление одного отражается по горизонтали — партнёр должен вести словами.
      Готово когда: зона визуально обозначена, эффект понятен без объяснений.

- [ ] **COOP-13 · Общий транспорт** `P2`
      Платформа, где один рулит, второй разгоняет — движется только при обоих действиях.
      Готово когда: без второго игрока транспорт стоит.

- [ ] **COOP-14 · Кооп-обучение** `P1`
      Зачем: асимметричные механики без обучения отпугивают на первой минуте.
      Готово когда: первая глава вводит по одной механике за раз, без текстовых стен.

## Ошибки, найденные и исправленные по ходу работы

Их не было в исходном плане — всплыли при чтении и правке кода. Перечислены, чтобы вы понимали,
что именно изменилось в поведении игры.

- **Прозрачность частиц применялась ко всем сразу.** `Effects` кэшировал материалы по цвету, а
  затухание выставлялось через `material.opacity` — то есть на общий для всех частиц объект. Вместо
  плавного угасания частицы одного цвета мигали вместе, принимая прозрачность той, что обновилась
  последней. Заменено на набор материалов по ступеням прозрачности.
- **Выталкивание из препятствий уходило в никуда.** После разделения позиции физики и позиции
  отрисовки метод `Course.interact` продолжал бы менять позицию отрисовки, которая пересчитывается
  заново каждый кадр. Любое выталкивание из бампера или вертушки немедленно затиралось бы. Исправлено
  до того, как попало в игру.
- **Постобработка отключала тональную компрессию.** `OutputPass` берёт кривую из
  `renderer.toneMapping`; выставленный там `NoToneMapping` означал, что компрессия не выполняется
  нигде, и картинка была полностью пересвечена.
- **Порог свечения задавался как будто в диапазоне 0..1.** Сцена освещена очень ярко, и в линейном
  HDR почти всё выше единицы, поэтому в свечение попадала вся картинка разом. Порог поднят до 2.2, а
  эмиссия тех объектов, которые действительно должны светиться, поднята им навстречу.
- **Мёртвый код.** Сообщение `checkpoint` отправлялось клиентом, но обработчика на сервере не имело;
  `bindNetworkEvents()` был пустой заглушкой; `fallGrace` в настройках сложности не читался нигде;
  параметр `side` в `addRail` не использовался.
- **404 на `/favicon.ico`.** Добавлен встроенный SVG-фавикон как data-URI, без файла-ассета.
