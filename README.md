# Wobble Rush 3D

Процедурный обстакл-рейсер на Three.js, обычных браузерных ES-модулях, Node.js и WebSocket. Одна и та
же детерминированная трасса собирается из сида и в одиночном забеге, и в онлайн-комнате до 16 игроков.

Проект развивается в сторону **кооперативного режима на двух игроков** в духе _It Takes Two_.

## Что есть сейчас

**Геймплей**

- Детерминированные процедурные трассы из семи типов сегментов: вертушки, движущиеся платформы,
  бамперы, узкие мосты, поршни, пружины, ветряки — и финальные ворота.
- У каждого типа пять **структурно разных** расстановок: встречное вращение или одна медленная
  балка во всю площадь, зигзаг из бамперов или ворота с проходами, сплошной мост или разорванный,
  балка под ногами или над головой. Проходимость каждой расстановки проверяется ботом.
- Движение относительно камеры, буфер прыжка, coyote time, рывок с переходом в перекат,
  сохранение темпа после точного приземления, перенос движущимися платформами, импульсы от
  препятствий, чекпоинты и быстрое возрождение.
- Анимированный персонаж с независимыми конечностями, козырьком и антенной; позы бега, прыжка и
  рывка, приседание при приземлении, таблички с именами в сети.
- Управление под сенсорный экран: джойстик, крупные кнопки, свайп для поворота камеры,
  автослежение и кнопка возврата камеры.
- Настройки управления и доступности: сторона джойстика под левую или правую руку, его размер,
  прозрачность и режим (фиксированный или под пальцем), чувствительность и инверсия осей,
  вибрация отдельно от звука, сила тряски, уменьшенная анимация, крупный интерфейс и своя
  раскладка клавиш.
- Косметические награды без валюты и магазина: новые корпуса, визоры, антенны, следы и эффект
  финиша открываются прохождением кампании, безупречными главами, спасениями и серией daily.
- Экран результатов объясняет попытку: сравнивает с прошлым рекордом, отмечает чистое прохождение,
  командные спасения, место и процент в таблице главы и прогресс к следующей награде.
- Ежедневная и случайная трассы, три сложности, медали, счётчик падений, личные рекорды.
- Из идущего забега можно выйти в меню — кнопка в HUD, с подтверждением вторым нажатием.
- Если напарник вышел посреди кооперативной главы, оставшийся её доигрывает: кооперативные преграды
  открываются, и глава не запирает того, кто остался один.

**Физика и графика**

- Фиксированный шаг физики 60 Гц с интерполяцией отрисовки: поведение персонажа одинаково на 60 и
  144 Гц, движение остаётся плавным при любой частоте кадров.
- Карта теней следует за игроком — тени есть на всём протяжении трассы.
- Постобработка со свечением на высоком качестве; кэш материалов; адаптивное качество, пониженные
  плотность пикселей и лимит частиц на слабых устройствах.
- Отзывчивый интерфейс с учётом безопасных зон экрана, портретная и альбомная раскладки.

**Звук**

- Полностью процедурный синтез на Web Audio API — **ни одного файла-ассета**: нулевой вес загрузки,
  мгновенная готовность и естественная вариативность.
- Около полутора десятков эффектов: прыжок, приземление с громкостью по силе удара, рывок, шаги,
  свист падения, пружина, бампер, вертушка, поршень, чекпоинт, финиш, интерфейс, обратный отсчёт.
- Пространственное позиционирование: слышно, с какой стороны напарник.
- Адаптивная музыка из слоёв — бас, ударные, аккорды, мелодия, — нарастающая по мере прохождения.
- Три регулятора громкости, сохраняются между сессиями.

**Сеть**

- Сервер владеет сидом и сложностью комнаты, сам выводит чекпоинты, проверяет движение и финиш,
  выдаёт возрождения и определяет порядок финиша.
- Проверка движения знает геометрию трассы: свой потолок скорости на каждое состояние персонажа,
  коридор опоры и полоса высоты стояния по плану сегментов, средняя скорость за окно в две секунды,
  минимальное время сегмента по его типу. Вне досягаемости препятствий работает только гравитация —
  этим ловятся и полёт над трассой, и обход её сбоку. Все пороги получены замером честных прогонов.
- Синхронизация часов с сервером: фаза препятствий одинакова у всех игроков независимо от того,
  насколько врут их системные часы.
- Буфер снапшотов с интерполяцией и отрисовкой на 100 мс в прошлом; экстраполяция по скорости при
  потере пакетов — напарник движется плавно, без рывков.
- Переподключение по токену сессии: слот игрока держится 30 секунд, права хоста сохраняются.
- Проверка источника при подключении сокета, ограничение частоты запросов по адресу, миграция хоста,
  голосование за реванш, показ задержки.
- Игровая статистика с разбивкой по режиму, трассе, препятствию и типу устройства копится в SQLite и
  переживает перезапуск: видно, на каком препятствии падают чаще всего и какие главы не проходят.
- Общая competitive-таблица рекордов у гонки и кооперативных глав принимает только server-timed
  подтверждённые забеги. В гонке движение проверяется по процедурной геометрии; в коопе отдельный
  CoopMovementAudit читает общую data-driven разметку главы, проверяет sustained speed, опоры,
  высоту, checkpoint regions и минимальное время участков, делая узкие исключения для подтверждённых
  сервером катапульт, троса и moving platform. Старые co-op строки, записанные до этой проверки,
  не повышаются до competitive задним числом. Соло остаётся только личным рекордом: сервера там нет.

## Запуск

Требуется Node.js 22.5 или новее. Две причины: `require()` для ES-модулей (так общий с клиентом
модуль правил трассы работает на обеих сторонах без сборщика) и встроенный `node:sqlite`, в котором
живёт таблица рекордов. Внешней базы и нативных модулей проект не требует.

```bash
npm install
npm start
```

Откройте `http://localhost:3000`. В кооперативе можно сразу нажать **«Найти напарника»**: сервер
соединит двух старейших игроков с совместимым выбором главы и сам запустит отсчёт. Флажок «любая
глава» ускоряет поиск и отдаёт приоритет выбору того игрока, который указал конкретную главу.

Для игры с другом остаются приватные комнаты: откройте второе окно или другое устройство по тому
же адресу, создайте комнату, войдите по пятисимвольному коду, отметьте готовность у обоих и
запустите забег с хоста.

Клиент берёт адрес `/ws` от текущей страницы. Отдельный сокет-хост задаётся до загрузки `main.js`:

```html
<script>
  window.WOBBLE_WS_URL = 'wss://your-socket-host.example/ws';
</script>
```

## Управление

- **Клавиатура**: WASD или стрелки — движение, Пробел — прыжок, Shift — рывок, перетаскивание мышью
  (или Q/E) — поворот камеры, R — вернуть камеру за спину.
- **Сенсор**: левый джойстик — движение, кнопки справа внизу — прыжок и рывок, свайп по свободной
  правой части экрана — поворот камеры, кнопка с перекрестием — вернуть камеру.
- После быстрого приземления рывок переходит в перекат; вовремя нажатый прыжок сохраняет темп и
  ускоряет выход. Прыжок у светящейся голубой стены выполняет wall-bounce — отдельная кнопка не
  нужна ни на клавиатуре, ни на телефоне.

Всё перечисленное — умолчания. Кнопка **УПРАВЛЕНИЕ** в подвале меню открывает настройки:

| Что                             | Значения                                                        |
| ------------------------------- | --------------------------------------------------------------- |
| Сторона джойстика               | слева или справа — кнопки и зона обзора переезжают вместе с ним |
| Тип джойстика                   | фиксированный или появляющийся под пальцем                      |
| Размер и прозрачность джойстика | 96…200 px, 20…100 %                                             |
| Чувствительность обзора         | 25…250 %                                                        |
| Инверсия осей                   | по горизонтали и по вертикали, независимо                       |
| Вибрация                        | 0…100 %, отдельно от звука                                      |
| Тряска экрана                   | 0…100 %                                                         |
| Анимация                        | как в системе, полная, уменьшенная                              |
| Размер интерфейса               | 100…160 %                                                       |
| Клавиши                         | своя раскладка на десять действий, до двух клавиш на каждое     |

Три вещи, которые стоит знать про эти настройки:

- **Вибрация не привязана к громкости.** На беззвучном телефоне звук — не обратная связь, а
  глухому игроку он не обратная связь вовсе. Свой регулятор и свой ноль.
- **«Как в системе» — не то же самое, что «уменьшенная».** Системный `prefers-reduced-motion`
  выставляют ради всей ОС и забывают; попросить меньше движения только в игре (или наоборот,
  оставить её живой при включённой системной настройке) — отдельное право игрока.
- **Нетронутая настройка не спорит с экраном.** Пока регулятор не двигали, размер джойстика и
  кнопок задают адаптивные правила — на узком телефоне они меньше. Тронутый регулятор побеждает.

Настройки хранятся в `localStorage` и проверяются по схеме в `client/core/settings.js`: чужое или
устаревшее значение заменяется умолчанием, а не ломает управление.

## Разработка

```bash
npm test          # правила сервера, сеть, физика, кооп, интеграция двух клиентов
npm run lint      # ESLint по всему проекту
npm run format    # Prettier
```

Клиентский вход разбит на части: `client/main.js` держит сцену, цикл и забег, а меню, сетевые
привязки, кооперативный режим, аккаунт и выбор качества живут отдельными модулями.

Тесты покрывают: очистку имён с юникодом, детерминизм трасс, серверную проверку чекпоинтов и финиша,
отклонение телепортов, проверку источника подключения, интерполяцию и экстраполяцию буфера снапшотов,
оценку расхождения часов, совпадение спеки трассы у клиента и сервера, независимость физики от частоты
кадров, интерполяцию отрисовки, кэш материалов, кооп-кадрирование камеры, а также реальный сценарий
двух WebSocket-клиентов с обрывом связи и возвратом в комнату. Отдельный набор играет за жульничающих
клиентов — скорость, полёт, обход трассы, стояние в пустоте, мгновенный сегмент — и требует, чтобы
каждый из них попался, а честный бот на настоящей физике прошёл трассу без единого признака.

Клиентские модули написаны для браузера, но прогоняются в Node без сборщика: загрузчик
`server/client-loader.mjs` подменяет браузерные пути импорта на файлы из `node_modules`, повторяя те
же соответствия, что задаёт import map в `client/index.html`.

## Структура

```
client/
  audio/      AudioEngine, библиотека эффектов, адаптивная музыка
  core/       конфигурация, ввод
  game/       трасса, игрок, персонаж, камера, частицы, постобработка
  net/        WebSocket-клиент, синхронизация часов, буфер снапшотов, реконсиляция
  ui/         экраны и HUD
shared/       правила трассы, симуляция движения, поиск опоры — общие для клиента и сервера
server/       раздача статики, комнаты, валидация, серверный авторитет, тесты
docs/         развёртывание, эксплуатация, миграция нетокода
```

Движение персонажа считает клиент; сервер проверяет его допустимость и владеет результатом —
чекпоинтами, финишем и таблицей рекордов. Прогресс гонки переводился на серверный авторитет по
одной границе за раз, каждая закрыта отдельными воротами готовности. Что переключено, что нет и
почему полный серверный авторитет движения снят с плана —
[`docs/NETCODE-MIGRATION.md`](docs/NETCODE-MIGRATION.md).

## Наблюдаемость

`/health` отвечает на вопрос «сервер жив»: комнаты, игроки, аптайм. `/health/live` и `/health/ready`
разделяют «процесс жив» и «сокеты принимаются» — балансировщику нужны разные ответы.

`/metrics/gameplay` отвечает на вопрос «как в это играют». Каждое событие разложено по четырём
измерениям: `mode` — режим; `course` — сложность гонки или идентификатор кооп-главы; `detail` —
подробность, своя у каждого события; `device` — телефон или компьютер, по User-Agent.

| Событие           | `detail`                                                     | Величина         |
| ----------------- | ------------------------------------------------------------ | ---------------- |
| `match_started`   | —                                                            | нет              |
| `match_finished`  | —                                                            | нет              |
| `match_abandoned` | чекпоинт, дальше которого не пошли (`cp3`)                   | нет              |
| `fall`            | тип препятствия в гонке (`bridge`), чекпоинт в коопе (`cp3`) | нет              |
| `finish_time`     | `verified` или `unverified`                                  | время забега, мс |

```
GET /metrics/gameplay?days=7&limit=200
{
  "days": 7,
  "from": "2026-08-02",
  "dropped": 0,
  "rows": [
    { "metric": "fall", "mode": "race", "course": "chaos", "detail": "bridge",
      "device": "mobile", "samples": 412, "average": null },
    { "metric": "finish_time", "mode": "race", "course": "easy", "detail": "verified",
      "device": "desktop", "samples": 89, "average": 41232 }
  ]
}
```

Строки идут от частого к редкому. `average` заполнено только у событий с величиной; у простых
счётчиков оно `null`, потому что ноль читался бы как настоящий ноль. Непроверенные времена не
выбрасываются, а лежат отдельной строкой: в коопе движение не проверяется вовсе, а в гонке зачёт
снимает и чужой обрыв связи — но смешивать их с проверенными нельзя, одного забега на три секунды
хватит, чтобы испортить среднее. `dropped` больше нуля означает, что в какое-то измерение попало
слишком много разных значений и часть событий отброшена, — это ошибка в коде, а не нагрузка.

Данные обезличены — это счётчики по типам препятствий и сложностям, ни одного игрока по ним не
найти. Копятся в памяти и сбрасываются в SQLite раз в пятнадцать секунд, поэтому падение в пропасть
не стоит обращения к диску. Хранятся 90 дней; при `LEADERBOARD_DB=:memory:` (по умолчанию) исчезают
вместе с процессом — для боевого сервера путь к файлу задать обязательно.

Наружу адрес не выпускается: в [`deploy/nginx-locations.conf`](deploy/nginx-locations.conf) у
`/metrics/` тот же запрет, что у `/health`. Смотреть с телефона —
`ssh -L 3000:127.0.0.1:3000 wobble@сервер`, дальше `localhost:3000/metrics/gameplay`.

## Развёртывание

**На свой VPS** — см. [`docs/DEPLOY.md`](docs/DEPLOY.md): установка одной командой, systemd,
Nginx с TLS, управление с телефона через Termux. Готовые конфиги лежат в [`deploy/`](deploy).

### На Render

1. Загрузите репозиторий на GitHub и создайте Render Blueprint.
2. Render читает `render.yaml`, выполняет `npm ci --omit=dev` и запускает один Node Web Service.
   Этот же сервис отдаёт клиента и `/ws`, поэтому отдельная настройка CORS не нужна.
3. `PORT` назначает Render. `NODE_ENV=production` и версия Node объявлены в Blueprint.
4. Дождитесь, пока `/health` начнёт отвечать `{"ok":true,...}`, и откройте HTTPS-адрес сервиса.
5. Проверьте на одном окне рабочего стола плюс телефоне. Сервис на бесплатном тарифе засыпает и
   просыпается несколько секунд; панель сетевой игры покажет состояние подключения и поставит первый
   запрос в очередь.

Переменная `ALLOWED_ORIGINS` (через запятую) задаёт список источников, которым разрешено открывать
сокет. Если не задана, разрешаются свой хост и localhost.

### За обратным прокси

Сервер ограничивает частоту по адресу клиента: 24 одновременных сокета и 40 операций с комнатами
в минуту. За прокси `remoteAddress` — это адрес самого прокси, один на всех, поэтому лимиты
начинают делиться между всеми игроками сразу. Установите `TRUST_PROXY=1`, и сервер будет брать
адрес из `X-Forwarded-For`; включать только когда Node недоступен из интернета напрямую
(`HOST=127.0.0.1`), иначе заголовок подделает кто угодно.

Готовый конфиг Nginx, systemd-юнит и разбор остальных настроек — в
[`docs/DEPLOY.md`](docs/DEPLOY.md) и [`deploy/`](deploy).

Клиент и `shared/` отдаются с `Cache-Control: no-cache, must-revalidate`: имена файлов без хеша, а
версия протокола должна совпадать у клиента и сервера. Не добавляйте им кэширование на прокси —
иначе после обновления часть игроков несколько минут будет говорить со свежим сервером старым
клиентом. Долгий кэш допустим только для `/vendor`.

Для проверки на мобильных устройствах пройдите хотя бы один узкий портретный экран и один низкий
альбомный. Убедитесь, что HUD не перекрывает игровую область и все элементы управления остаются
внутри безопасных зон экрана.
