# Развёртывание на своём VPS

Инструкция для чистого Ubuntu 22.04/24.04 или Debian 12 — то, что обычно даёт хостинг вроде
aeza.ru. Управлять сервером будем с телефона через Termux; с компьютера всё то же самое, просто
пропустите первый раздел.

Игра — один Node-процесс: он отдаёт и клиента, и WebSocket на `/ws`. Отдельный веб-сервер для
статики не нужен. Nginx впереди нужен для другого: TLS, ограничение доступа к метрикам и
нормальные адреса клиентов в лимитах.

---

## 1. Termux: подготовка телефона

```bash
pkg update && pkg upgrade -y
pkg install -y openssh
```

Дальше — **ключ вместо пароля**. Это не про безопасность ради безопасности: набирать длинный
пароль на телефонной клавиатуре при каждом подключении вы бросите на третий раз, а короткий
пароль на сервере с публичным адресом подберут за сутки.

```bash
ssh-keygen -t ed25519 -C "termux"        # на все вопросы можно жать Enter
ssh-copy-id root@ВАШ_IP                  # один раз спросит пароль
ssh root@ВАШ_IP                          # дальше — уже без пароля
```

Если `ssh-copy-id` недоступен, то же самое руками:

```bash
cat ~/.ssh/id_ed25519.pub | ssh root@ВАШ_IP 'mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys'
```

Чтобы не набирать адрес каждый раз, добавьте в `~/.ssh/config` на телефоне:

```
Host wobble
    HostName ВАШ_IP
    User root
    ServerAliveInterval 30
```

После этого подключение — просто `ssh wobble`. `ServerAliveInterval` важен: мобильная сеть рвётся,
и без него сессия зависает вместо того, чтобы честно отвалиться.

**Обязательно поставьте на сервере `tmux`** и работайте внутри него. У телефона связь пропадает
в лифте, в метро и при звонке — установка, начатая в голом ssh, оборвётся на середине.

```bash
ssh wobble
apt-get update && apt-get install -y tmux
tmux new -s deploy        # войти в сессию
# ... работаем ...
# отключиться, не убивая: Ctrl+B, потом D
tmux attach -t deploy     # вернуться после обрыва
```

## 2. Установка одной командой

На сервере, внутри tmux:

```bash
# С доменом — рекомендуется:
DOMAIN=ваш-домен.ru bash <(curl -fsSL https://raw.githubusercontent.com/Malikk-Sh/Fall-guys/main/deploy/install.sh)

# Без домена, по адресу сервера:
bash <(curl -fsSL https://raw.githubusercontent.com/Malikk-Sh/Fall-guys/main/deploy/install.sh)
```

Скрипт ставит Node 22, Nginx и файрвол, создаёт системного пользователя `wobble`, разворачивает
код в `/opt/wobble`, поднимает службу `wobble` и проверяет, что сервер отвечает. Повторный запуск
обновляет игру до свежего `main` и перезапускает службу — ничего не ломая.

Что именно он делает, расписано в [`deploy/install.sh`](../deploy/install.sh); там же видно, какие
файлы он трогает. Если не хотите запускать скрипт из интернета не глядя — склонируйте репозиторий
и запустите `bash deploy/install.sh` из него.

**Если на сервере уже что-то работает** — VPN, панель, другой сайт — сразу переходите к
разделу 3б: там разобран занятый порт 443 и объяснено, почему скрипт в этом случае не включает
файрвол сам.

## 3. HTTPS

Нужен домен: Let's Encrypt не выдаёт сертификаты на голый IP-адрес. Подойдёт любой, в том числе
дешёвый в зоне `.ru`. В A-записи домена укажите адрес сервера и подождите, пока она разойдётся
(обычно минуты, иногда часы).

```bash
apt-get install -y certbot python3-certbot-nginx
certbot --nginx -d ваш-домен.ru
```

Certbot сам допишет конфиг Nginx и настроит автопродление. Проверить продление:
`certbot renew --dry-run`.

После выпуска сертификата поправьте разрешённые источники:

```bash
nano /etc/wobble.env      # ALLOWED_ORIGINS=https://ваш-домен.ru
systemctl restart wobble
```

**Почему это не «на потом».** Без HTTPS у мобильных браузеров отключены `navigator.share` и
работа с буфером обмена, а игра ориентирована на телефоны — кнопка «поделиться ссылкой-приглашением»
просто не сработает. Плюс клиент выбирает `ws://` или `wss://` по протоколу страницы: на `http://`
соединение пойдёт открытым текстом.

## 3б. Если порт 443 уже занят (VPN на том же сервере)

Обычный путь из раздела выше предполагает, что 443 свободен. Если там уже работает VPN — Xray,
WireGuard, что угодно, — забирать у него порт не надо: именно на 443 такой трафик и выглядит
обычным HTTPS, а переезд на другой порт делает его заметным. Отдаём игре другой порт.

Порт 80 всё равно нужен: проверка Let's Encrypt ходит только на 80 и 443, другого способа
выпустить сертификат на домен нет. Nginx займёт 80 и отдаст с него проверочные файлы.

```bash
# 1. Первый запуск: поднимет игру и порт 80 под проверку.
DOMAIN=ваш-домен.ru HTTPS_PORT=8443 bash /opt/wobble/deploy/install.sh

# 2. Сертификат. Плагин --nginx здесь НЕ подходит: он попытается занять 443, который занят
#    вашим VPN, и уронит конфигурацию Nginx. Выпускаем через каталог проверки.
apt-get install -y certbot
certbot certonly --webroot -w /var/www/certbot -d ваш-домен.ru \
  --agree-tos --register-unsafely-without-email --non-interactive \
  --deploy-hook "systemctl reload nginx"

# 3. Повторный запуск допишет TLS на 8443.
DOMAIN=ваш-домен.ru HTTPS_PORT=8443 bash /opt/wobble/deploy/install.sh
```

Игра окажется на `https://ваш-домен.ru:8443`. Порт в адресе — плата за занятый 443; на работу
кооператива это не влияет, ссылка-приглашение несёт его с собой.

`--deploy-hook` не украшение: сертификат продлевается автоматически, но Nginx сам об этом не
узнает и будет отдавать старый до перезапуска.

### Что скрипт делает иначе в этом режиме

- **Не включает файрвол.** На сервере с VPN включение ufw с одними лишь нашими правилами
  закрыло бы порт VPN и панель управления — то есть отрубило бы вам доступ туда, куда вы
  заходили минуту назад. Правила добавляются, а включение остаётся за вами:
  `ufw status`, убедиться, что все нужные порты в списке, потом `ufw enable`. Либо сразу
  `ENABLE_FIREWALL=1`, если сервер только под игру.
- **Пишет `ALLOWED_ORIGINS` вместе с портом** — `https://домен:8443`. Без порта сервер не
  признает Origin своим и откажется открывать WebSocket.
- **Передаёт `Host` с портом** (`$http_host`, а не `$host`). Это та же причина: сервер сверяет
  Origin с заголовком Host, и без порта они не совпадут. Симптом был бы неочевидный — игра
  открывается, а напарник не подключается.

### Переход с pm2

Если игра уже запущена через pm2, сначала уберите её — иначе оба менеджера возьмут порт 3000
и вы получите `EADDRINUSE`:

```bash
pm2 delete wobble-rush
pm2 save
```

Старый каталог с игрой можно оставить: скрипт разворачивает свою копию в `/opt/wobble` и не
трогает то, что лежало раньше.

## 4. Что где лежит

| Что       | Где                                  |
| --------- | ------------------------------------ |
| Код       | `/opt/wobble`                        |
| Настройки | `/etc/wobble.env` (права 600)        |
| Служба    | `/etc/systemd/system/wobble.service` |
| Nginx     | `/etc/nginx/sites-available/wobble`  |
| Логи      | `journalctl -u wobble`               |

Команды на каждый день:

```bash
systemctl status wobble          # жив ли
journalctl -u wobble -f          # логи вживую
journalctl -u wobble -n 100      # последние сто строк
systemctl restart wobble         # перезапустить
bash /opt/wobble/deploy/install.sh   # обновить до свежего main
curl -s localhost:3000/health | head -c 400   # метрики
```

### Миграции базы

При старте сервер сам применяет ещё не выполненные файлы из `server/migrations/` строго по номеру.
Результат записывается в `schema_migrations(version, applied_at)`, поэтому повторный рестарт не
выполняет один и тот же SQL снова. Каждая миграция и отметка о ней находятся в одной транзакции:
если SQL завершился ошибкой, база откатывается целиком и служба не стартует на половине схемы.

Перед обновлением всё равно полезно сохранить SQLite-файл:

```bash
systemctl stop wobble
cp /var/lib/wobble/leaderboard.db /var/lib/wobble/leaderboard.db.bak
systemctl start wobble
sqlite3 /var/lib/wobble/leaderboard.db 'SELECT version, applied_at FROM schema_migrations;'
```

Уже выпущенную миграцию нельзя редактировать: следующая правка схемы получает новый файл
`003_...`, затем `004_...` и так далее. Сервер также откажется запускать старый код поверх базы,
в которой уже отмечена неизвестная ему более новая версия.

## 5. Настройки в `/etc/wobble.env`

| Переменная        | Зачем                                                                                                                                                                                                                                                                              |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PORT`            | Порт Node. Наружу не смотрит.                                                                                                                                                                                                                                                      |
| `HOST=127.0.0.1`  | Слушать только локально. Без этого порт 3000 доступен из интернета в обход Nginx — без TLS и без ограничений, и заметить это трудно: игра ведь работает.                                                                                                                           |
| `TRUST_PROXY=1`   | Разбирать `X-Forwarded-For`. За Nginx адрес соединения всегда `127.0.0.1`, один на всех, и лимиты «24 сокета и 40 операций с комнатами в минуту с адреса» делятся между всеми игроками сразу. Включать **только** вместе с `HOST=127.0.0.1`, иначе заголовок подделает кто угодно. |
| `ALLOWED_ORIGINS` | Кто может открывать WebSocket. Защита от того, что игру встроят на чужой сайт и будут гонять ваш сервер оттуда.                                                                                                                                                                    |

## 6. Сколько игроков потянет сервер

Проверено пробой `npm run load` — она поднимает настоящие WebSocket-клиенты и гоняет их с той же
частотой, что и браузер:

|                              |                                   |
| ---------------------------- | --------------------------------- |
| Без игроков                  | 68 МБ памяти                      |
| 24 игрока в 12 кооп-комнатах | 70 МБ памяти, **3 % одного ядра** |

То есть комната обходится примерно в 0.2 МБ и 0.25 % ядра. **Одного ядра и двух гигабайт хватает
с большим запасом** — счёт идёт на сотни одновременных пар, и раньше упрётесь в канал или в
собственную аудиторию, чем в железо.

Сервер однопоточный, поэтому вторым ядром он всё равно не воспользуется: если когда-нибудь
упрётесь, увеличивать надо не мощность машины, а число процессов — и тогда понадобится общее
хранилище комнат, потому что сейчас они живут в памяти одного процесса. Это отдельная работа.

Проверить на своём сервере:

```bash
cd /opt/wobble && npm run load
```

Смотреть стоит на строки «процессор» и «сбоев отправки». Если процессор ушёл за 60 %, а сбои
отправки не ноль — вот тогда пора думать о втором процессе.

## 7. Обновление игры

```bash
ssh wobble
tmux new -s deploy
bash /opt/wobble/deploy/install.sh
```

Скрипт подтянет свежий `main`, переустановит зависимости и перезапустит службу. Простой — секунды.

Домен и порт повторять не нужно: значения последнего удачного развёртывания лежат в
`/etc/wobble-deploy.conf` и подставляются сами. Первой же строкой скрипт печатает, что именно
разворачивает, — если там не то, что вы ожидали, прервите его, пока он ничего не изменил.
Чтобы поменять настройки, передайте переменные явно: окружение важнее запомненного.

**Сервер и клиент обновляются вместе.** У протокола есть версия, и при несовпадении клиент
отказывается работать, показывая «обновите страницу». Поэтому клиент и `shared/` отдаются с
`Cache-Control: no-cache` — не добавляйте им кэширование на стороне Nginx или CDN, иначе часть
игроков после обновления будет несколько минут говорить со свежим сервером старым клиентом.

## 8. Если что-то не работает

**Игра не открывается.** Проверьте по очереди, что жив каждый слой:

```bash
systemctl status wobble                     # процесс
curl -s localhost:3000/health | head -c 200 # приложение
nginx -t && systemctl status nginx          # прокси
ufw status                                  # файрвол
```

**Открывается, но напарник не подключается.** Почти всегда это WebSocket: смотрите в консоли
браузера ошибку на `/ws`. Частые причины — отсутствует блок `location /ws` с заголовками `Upgrade`,
либо `ALLOWED_ORIGINS` не совпадает с адресом, по которому реально открыта страница (например,
задан `https://`, а зашли по `http://`).

**После обновления сайт открывается по адресу сервера вместо домена, HTTPS пропал.** Так вели себя
установки, развёрнутые до августа 2026: скрипт не запоминал домен и порт, и запуск без переменных
разворачивал всё заново «как в первый раз», заменяя рабочий конфиг с TLS на обычный HTTP. Лечится
одним запуском с явными значениями — дальше они запомнятся:

```bash
DOMAIN=ваш-домен.ru HTTPS_PORT=8443 bash /opt/wobble/deploy/install.sh
```

**Игроков выкидывает с ошибкой «слишком много запросов».** Не выставлен `TRUST_PROXY=1`, и все
игроки для сервера выглядят одним адресом.

**Соединение рвётся каждые несколько десятков секунд.** `proxy_read_timeout` в Nginx меньше
периода heartbeat сервера (15 с). В приложенном конфиге стоит 75 с.

**Сервер перезапускается сам.** `journalctl -u wobble -n 200` покажет причину. Скорее всего не
хватает памяти: игре достаточно 512 МБ, но если на том же VPS крутится что-то ещё, стоит
проверить `free -m`.

**Скрипт обрывается на `detected dubious ownership in repository at '/opt/wobble'`.** Так вели себя
установки, развёрнутые до августа 2026: каталог принадлежит пользователю `wobble`, а git запускается
от root, и с версии 2.35 он на такое несовпадение ругается. Скрипт теперь добавляет исключение сам,
но на уже развёрнутом сервере его нужно один раз прописать вручную:

```bash
git config --global --add safe.directory /opt/wobble
```

**Скрипт обрывается на `unknown directive "http2"`.** Отдельная директива `http2 on;` появилась
только в nginx 1.25.1, а в Ubuntu 24.04 ставится 1.24. Скрипт теперь проверяет конфиг через
`nginx -t` и, если директиву не приняли, записывает http2 прежним способом — параметром у `listen`.
Если конфиг уже написан и переустанавливать не хочется, то же самое делается вручную:

```bash
sed -i -e '/^\s*http2 on;$/d' \
       -e 's/^\(\s*listen 8443\) ssl;/\1 ssl http2;/' \
       -e 's/^\(\s*listen \[::\]:8443\) ssl;/\1 ssl http2;/' \
       /etc/nginx/sites-available/wobble
nginx -t && systemctl reload nginx
```
